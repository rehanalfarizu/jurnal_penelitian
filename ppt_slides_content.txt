SLIDE 2 — LATAR BELAKANG
================================================================================
1. KONTEKS
   - Bangunan cerdas mengonsumsi ~40% energi global dan menghasilkan ~30%
     emisi gas rumah kaca.
   - Estimasi konsumsi daya secara near-real-time dibutuhkan untuk optimasi energi,
     preventive maintenance, dan integrasi Digital Twin.

2. MASALAH TEKNIS
   - Arsitektur cloud-only mengalami latensi tinggi (~275 ms) yang tidak layak
     untuk kontrol near-real-time.
   - Arsitektur edge-only menghemat latensi (<2 ms) tapi kehilangan komputasi
     berat untuk model kompleks dan sinkronisasi Digital Twin.

3. SOLUSI: ARSITEKTUR EDGE-CLOUD HYBRID
   - Rekaman normal (96,8%) diproses di edge dengan latensi <2 ms.
   - Rekaman anomali (3,2%) dialihkan ke cloud untuk pemrosesan berat dan
     sinkronisasi Digital Twin Web-3D.

4. TANTANGAN RISET
   - Model streaming cenderung mengalami drift akumulasif seiring waktu,
     menurunkan kualitas prediksi.
   - Belum ada studi yang mengkuantifikasi pengaruh drift pada pipeline
     estimasi daya edge-cloud secara eksplisit.

SLIDE 4 — BATASAN MASALAH
================================================================================
1. DATA
   - Menggunakan dataset sensor IoT: 2.027.520 rekaman, 8 kolom
     (suhu, kelembaban, tegangan, arus, daya, jumlah_orang, jam, device_id).
   - Data berasal dari ESP32 (DHT11, ZMPT101B, SCT013) dan RPi Gateway,
     dikumpulkan selama ~89 hari.

2. MODEL
   - Fokus pada model Ridge Regression (streaming) dan Random Forest (batch)
     untuk estimasi daya.
   - Deteksi anomali menggunakan z-score pada composite energy_score.
   - Fitur: 19 fitur (5 sensor + 1 interaksi VxI + 3 rolling + 5 one-hot
     + 5 time period).

3. ARSITEKTUR
   - Edge processing: preprocessing + sensor fusion + anomaly detection +
     prediksi Ridge (~1,3 ms total per tahap).
   - Cloud processing: network transfer (45 ms) + heavy processing (150 ms)
     + Digital Twin sync (80 ms) = ~275 ms.
   - Nilai latensi cloud bersifat asumsi skenario akademik, belum diukur
     melalui benchmark round-trip jaringan nyata.

4. DIGITAL TWIN
   - Modul Digital Twin Web-3D diposisikan sebagai "Implemented Reference
     Architecture / Prototype" (Vue 3 + Babylon.js), bukan platform yang
     tervalidasi secara penuh.
   - Belum ada physics-based thermal simulation atau per-room energy
     breakdown.

SLIDE 7 — HASIL PENELITIAN (2 dari 2)
================================================================================

E. DRIFT ABLATION STUDY (Penjelasan Gap R^2)
   -----------------------------------------------------------------------
   - Gap R^2 batch vs streaming: 0,0323
   - Setelah drift di-stripping, gap menutup menjadi 0,0021
   - Persentase gap yang dijelaskan oleh drift: 93,5%
   -> Drift akumulatif (random-walk) EXPLAINING hampir seluruh penurunan
      performa streaming, bukan kelemahan model.
   - Drift signal max: 14,67 W (48x dari noise std = 0,15 W)

F. DRIFT-STRIPPED R^2 (Verifikasi)
   -----------------------------------------------------------------------
   - Ridge + drift stripped:    R^2 = 0,9973
   - Random Forest + drift stripped: R^2 = 0,9973
   -> Kedua model mencapai akurasi batch ketika drift dieliminasi.

G. ROBUSTNESS AUDIT - NEAR vs FAR ANOMALI
   -----------------------------------------------------------------------
   - FAR dari anomali (90,4% data): R^2 = 0,157, RMSE = 3,43 W
   - NEAR anomali (9,6% data):      R^2 = -0,095, RMSE = 3,73 W
   - Delta R^2: -0,2519
   -> Model Ridge di NEAR anomali WORSE THAN naive mean baseline!
      Ini temuan penting: drift terkonsentrasi di sekitar event anomali.

H. ANOMALY DETECTION PERFORMANCE
   -----------------------------------------------------------------------
   - Recall hard anomaly: 65,00%
   - Recall soft anomaly: 43,85%
   - Combined recall:     45,77%
   - False Positive Rate: 3,36% (68.092 dari 2.025.320 clean records)
   - Detection latency: median=0 records, mean=37 records

SLIDE 8 — KESIMPULAN
================================================================================
1. ARSITEKTUR EDGE-CLOUD HYBRID VALID
   - Hybrid Edge-Preferred mencapai latensi rata-rata 12,72 ms dengan hanya
     3,4% rekaman di-route ke cloud.
   - 152x lebih cepat dibanding Full-Cloud (275 ms) dengan biaya energi
     yang hampir identik (~20,4 mW).
   - Compute throughput 3.335 rec/s memberi headroom >10.000x di atas
     data arrival rate 0,3 rec/s.

2. DRIFT AKUMULATIF PENYEBAB UTAMA PENURUNAN R^2 STREAMING
   - 93,5% gap R^2 batch (0,9952) vs streaming (0,9629) dijelaskan oleh
     drift akumulatif, bukan keterbatasan model.
   - Ketika drift di-stripping, R^2 streaming mencapai 0,9973 - setara
     batch reference.
   - Insight: model online maintenance (retrain berkala atau drift
     compensation) dapat mempertahankan akurasi tinggi.

3. MODEL STREAMING REDUP DI SEKITAR ANOMALI KERAS
   - R^2 di area dekat anomali turun menjadi -0,095 (lebih buruk dari
     baseline naif mean).
   - Drift terkonsentrasi di sekitar event anomali.
   - Membuka arah riset: adaptive drift compensation layer.

4. DETEKSI ANOMALI MEMUASKAN UNTUK HARD ANOMALI
   - Recall 65% untuk hard anomaly dengan FPR hanya 3,36%.
   - Limitasi: precision rendah (1,46%) karena z-score threshold 2,5
     terlalu sensitif terhadap distribusi data.

5. DIGITAL TWIN WEB-3D: REFERENCE ARCHITECTURE
   - Implementasi frontend (Vue 3 + Babylon.js) dan firmware IoT (ESP32)
     telah ada sebagai reference architecture / prototype.
   - Limitasi: belum ada physics-based simulation, evaluasi prediksi vs
     terukur per ruangan masih terbuka untuk future work.

6. KETERBATASAN STUDI
   - Nilai latensi cloud bersifat asumsi skenario akademik (belum
     diukur via benchmark round-trip jaringan nyata).
   - Target daya approx V x I, sehingga akurasi R^2=0,995 merepresentasikan
     "estimasi daya" bukan "prediksi energi eksogen."
